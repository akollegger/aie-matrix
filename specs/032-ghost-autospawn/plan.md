# Implementation Plan: Ghost Agent Autospawning

**Branch**: `032-ghost-autospawn` | **Date**: 2026-06-16 | **Spec**: [spec.md](./spec.md)

## Summary

Two additive changes ensure ghost agents spawn automatically whenever a live session is active — either at startup (for pod restarts) or at session creation (for new sessions). No new services, no architectural changes, no breaking contract modifications.

1. **agent-host startup reconciliation** — a non-blocking async bootstrap in `main.ts` that checks for an active live session on startup and calls `spawnRosterForAgent` for every `rosterAgent: true` catalog entry.
2. **random-agent roster endpoint** — `GET /v1/roster` returning N synthetic wanderer entries, plus `rosterAgent: true` in the agent card, so the existing `spawnRosterForAgent` path handles wanderers identically to NPC characters.

## Implementation Slices

### Slice A — random-agent roster endpoint (P1, prerequisite for B)

**Files**: `ghosts/random-agent/src/agent.ts`, `ghosts/random-agent/src/buildAgentCard.ts`, `ghosts/random-agent/tests/roster.test.ts`

1. Add `rosterAgent: true` to the `matrix` block in `buildWandererAgentCard` in `buildAgentCard.ts`
2. In `agent.ts`, read `RANDOM_AGENT_COUNT` env var (default 10) and add:
   ```ts
   app.get("/v1/roster", (_req, res) => {
     const count = Math.max(0, parseInt(process.env.RANDOM_AGENT_COUNT ?? "10", 10) || 10);
     const roster = Array.from({ length: count }, (_, i) => ({
       characterId: `wanderer-${i + 1}`,
       displayName: `Wanderer ${i + 1}`,
     }));
     res.json(roster);
   });
   ```
3. Update `catalog.json` local dev entry to include `rosterAgent: true` in `agentCard.matrix`
4. Write `roster.test.ts` covering: default count (10), configured count, zero count, response schema

**Verification**: `pnpm --filter @aie-matrix/random-agent test` passes. `curl http://127.0.0.1:4001/v1/roster` returns 10 entries.

### Slice B — agent-host startup reconciliation (P1)

**Files**: `server/agent-host/src/main.ts`

In the `app.listen(...)` callback, after the existing Colyseus bridge and Barnacle bootstraps, add:

```ts
// Only skip if explicitly disabled (e.g. test environments without a live world-api)
const reconciliationEnabled = process.env.AGENT_HOST_DISABLE_RECONCILIATION !== "1";
if (reconciliationEnabled) {
  void (async () => {
    try {
      // Check for active live session
      const liveRes = await fetch(`${worldApiUrl}/live?status=active`,
        { signal: AbortSignal.timeout(10_000) });
      if (!liveRes.ok) return;
      const sessions = await liveRes.json() as Array<{ id: string }>;
      if (!Array.isArray(sessions) || sessions.length === 0) {
        log.info({ kind: "agent-host.startup-reconciliation.no-active-session" });
        return;
      }
      log.info({ kind: "agent-host.startup-reconciliation.found-session",
        sessionId: sessions[0]!.id });

      // Spawn roster for every rosterAgent in catalog
      const supervisor = await runtime.runPromise(
        pipe(AgentSupervisor, Effect.map((s) => s))
      );
      const catalog = await runtime.runPromise(
        pipe(CatalogService, Effect.map((c) => c))
      );
      const catalogFile = await runtime.runPromise(catalog.load());
      for (const [agentId, entry] of Object.entries(catalogFile.agents)) {
        if (entry.kind === "mini-game") continue;
        const isRoster =
          (entry.agentCard as { matrix?: { rosterAgent?: boolean } })
            .matrix?.rosterAgent === true;
        if (!isRoster) continue;
        const result = await runtime.runPromise(
          supervisor.spawnRosterForAgent(agentId, entry.baseUrl)
        );
        log.info({ kind: "agent-host.startup-reconciliation.roster-spawn-complete",
          agentId, spawned: result.spawned.length, failed: result.failed.length });
      }
    } catch (e) {
      console.error(JSON.stringify({
        kind: "agent-host.startup-reconciliation.failed",
        message: e instanceof Error ? e.message : String(e),
      }));
    }
  })();
}
```

**Verification**: Restart agent-host with an active session running. Logs show `startup-reconciliation.found-session` and `roster-spawn-complete`. Ghosts appear in Intermedium.

**Note on unit testing**: The reconciliation bootstrap in `main.ts` is glue code between already-tested services (`spawnRosterForAgent`, `catalog.load`). The critical testable behavior is in `spawnRosterForAgent` (already has tests) and in random-agent's `/v1/roster` endpoint (Slice A). Integration-level verification is via the quickstart manual steps.
