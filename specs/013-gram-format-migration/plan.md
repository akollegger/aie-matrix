# Implementation Plan: .map.gram Format Migration

**Branch**: `013-gram-format-migration` | **Date**: 2026-05-03 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/013-gram-format-migration/spec.md`

## Summary

Introduce a shared workspace package (`@aie-matrix/map-gram`) that parses the layered `.map.gram` format using the `@relateby/pattern` Gram AST — no regex. Both the Colyseus map loader and the intermedium client replace their existing parsers with thin adapters over this shared package. The `tmj-to-gram` serializer is updated to emit the same layered format (Layer walks + LayerStack + Rules). Existing old-format maps are regenerated by re-running the updated tool against their `.tmj` sources.

## Technical Context

**Language/Version**: TypeScript 5.7 / Node.js 24 (ESM, `"type": "module"`)  
**Primary Dependencies**: `@relateby/pattern` (Gram AST), `h3-js` 4 (polygon fill, cell math), `effect` v3+ (async plumbing), `@colyseus/core` 0.15.57 (consumer), `vitest` (tests)  
**Storage**: File-based — `.map.gram` files in `maps/`; no database  
**Testing**: `vitest` unit tests per package; existing integration tests in `server/colyseus/test/`  
**Target Platform**: Node.js 24 (Colyseus, shared package, tools) + browser via Vite (intermedium client) — shared package must use no Node-only APIs  
**Project Type**: Library (`@aie-matrix/map-gram`) + modifications to three existing packages  
**Performance Goals**: Parse any map in `maps/sandbox/` in under 1 second on a developer laptop  
**Constraints**: Shared package must be importable in both Node.js and browser (no `fs`, no `path`); H3 resolution fixed at 15; polygon vertices sorted by centroid angle before fill (reference implementation in map editor)  
**Scale/Scope**: ~6 map files; 4 packages affected; ~1 new package added

## Phase 0: Research

*See [research.md](./research.md) for full findings. Summary:*

All technical unknowns resolved prior to planning. Key decisions:

| Decision | Chosen | Rationale |
|---|---|---|
| Gram parsing strategy | AST walk via `Gram.parse()` | Full structure recovery; no regex fragility; map-editor already uses this pattern |
| Polygon fill API | `polygonToCellsExperimental(..., 15, POLYGON_TO_CELLS_FLAGS.containmentOverlapping)` | Exact algorithm used by map editor; vertex cells always included |
| Vertex sort order | Sort by angle from centroid before passing to fill | Prevents self-intersecting rings; mirror of map-editor reference impl |
| Shared package runtime | Pure ESM, no Node-only imports | Must run in browser (intermedium) and Node (Colyseus, tools) |
| Col/row in CellRecord | Set to 0 for gram-loaded maps | Col/row are Tiled artefacts; no Colyseus consumer reads them for routing |
| tmj-to-gram changes | Serializer only (`serialize-gram.ts`); data-gathering modules unchanged | Data collection (cell-emission, tile-area, item-emission) already produces the right inputs; only output format changes |

## Phase 1: Design & Contracts

### Shared package public API (`@aie-matrix/map-gram`)

```typescript
// Primary entry point
export function parseMapGram(gramText: string): Promise<ParsedMap>

// Types
export interface ParsedMap {
  name: string
  elevation: number
  tileTypes: Map<string, TileTypeDef>
  itemTypes: Map<string, ItemTypeDef>
  cells: Map<string, ParsedCell>   // keyed by h3Index
  portals: ParsedPortal[]
  rules: ParsedRule[]
}

export interface ParsedCell {
  h3Index: string
  tileType: string    // canonical TypeName label (e.g., "Floor", "Pillar")
  items: string[]     // ItemType names placed here
}

export interface ParsedPortal {
  fromCell: string
  toCell: string
  mode: string
}

export interface ParsedRule {
  fromType: string
  toType: string
}
```

### Colyseus adapter

`mapLoader.gram.ts` converts `ParsedMap` → `LoadedMap`:
- For each `ParsedCell`, build `CellRecord` with `col: 0, row: 0` (unused fields), `tileClass` from `parsedCell.tileType`, `initialItemRefs` from `parsedCell.items`
- Compute `neighbors` by running existing `assignCompassToNeighbors` from `hexCompass.ts` against the set of h3 cells in `parsedMap.cells`
- `anchorH3` set to the lexicographically first cell (or a map-level property if added to the format later)

### Intermedium adapter

`gramParser.ts` replaces its body with a call to `parseMapGram`, then maps `ParsedCell` → `WorldTile`:
- `tileType`: lowercase first char of `parsedCell.tileType`
- `items`: frozen copy of `parsedCell.items`
- `neighbors`: `h3.gridDisk(h3Index, 1).filter(c => c !== h3Index)` (all 6 adjacent, regardless of map occupancy — matches existing behaviour)

### tmj-to-gram serializer changes

`serialize-gram.ts` emits three new constructs:
1. **Polygon layer**: group `TileAreaPolygon` objects → `[id:Layer {kind: "polygon"} | (:Polygon:TypeName { geometry: [h3`v0`, ...] })]`
2. **Tile layer**: group `CellEmission` objects that are NOT implied by a polygon → `[id:Layer {kind: "tile"} | (:Tile:TypeName { geometry: [h3`...`] })]`
3. **Items layer**: group `ItemInstanceEmission` objects → `[id:Layer {kind: "items"} | (:Item:TypeName { geometry: [h3`...`] })]`
4. **LayerStack**: `[layers:LayerStack | polygonLayerId, tileLayerId, itemsLayerId]`
5. **Rules**: one self-rule per TileType: `(typeId)-[:GO]->(typeId)` (as before, auto-generated)

Old flat cell nodes (`(cell-<h3>:Type { location: h3\`...\` })`) are replaced entirely.

### world-api validation update

`MapService.ts` validation tightens: a valid `.map.gram` must contain a `LayerStack` subject (in addition to the existing `kind: "matrix-map"` header check). Files without `LayerStack` are rejected at startup.
